# Contract Error Reference

All `ContractError` codes returned by VoteChain smart contracts as `u32` values.
This reference is generated by hand from `contracts/governance/src/types.rs`
and `contracts/token/src/types.rs`; when either enum changes, update the
matching table below in the same PR (see [CI validation](#ci-validation)).

---

## Governance Contract

Source: [`contracts/governance/src/types.rs`](../contracts/governance/src/types.rs)
(all `return Err(...)` sites below are in
[`contracts/governance/src/lib.rs`](../contracts/governance/src/lib.rs) unless noted).

| Code | Name | Description | Raised by | Resolution |
|------|------|-------------|-----------|------------|
| 1 | `AdminNotSet` | Contract has not been initialized — no admin address is stored. | Internal `storage::get_admin()`, called by every admin-gated function (`execute`, `cancel`, `update_quorum`, `pause`, `transfer_admin`, etc.) | Call `initialize(admin, voting_token)` before invoking any other function. |
| 2 | `NotAdmin` | Caller is not the configured admin address. | `execute`, `execute_parameter_change_override`, `cancel`, `update_quorum`, `update_max_proposals`, `update_timelock`, `transfer_admin`, `propose_admin_transfer`, `pause`, `unpause`, `upgrade` | Sign the transaction with the admin keypair set during `initialize`. |
| 3 | `VotingTokenNotSet` | The governance token address was not set during initialization. | Internal `storage::get_voting_token()`, called wherever the voting token balance/supply is read | Re-initialize the contract with a valid `voting_token` address. |
| 4 | `InvalidQuorum` | `quorum` is zero or negative. | `create_proposal`, `update_quorum` | Provide a quorum value greater than zero (denominated in token units). |
| 5 | `InvalidDuration` | `duration` passed to `create_proposal` is zero. | `create_proposal` | Provide a duration of at least 1 ledger. |
| 6 | `ProposalNotFound` | No proposal exists for the given `proposal_id`. | `cast_vote`, `cast_vote_with_delegators`, `finalise`, `execute`, `cancel`, `update_quorum`, `get_proposal`, `has_voted`, `get_votes` | Verify the ID with `proposal_count()` — valid IDs are in the range `[1, proposal_count]`. |
| 7 | `ProposalNotActive` | The proposal is not in `Active` status (e.g. already Passed, Rejected, Executed, or Cancelled). | `cast_vote`, `cast_vote_with_delegators`, `finalise`, `cancel`, `update_quorum` | Check the proposal status with `get_proposal(proposal_id)` before calling the function. |
| 8 | `VotingPeriodEnded` | The current ledger timestamp is past the proposal's `end_time`. | `cast_vote`, `cast_vote_with_delegators` | The voting window has closed; call `finalise(proposal_id)` to settle the result. |
| 9 | `VotingStillOpen` | `finalise` was called before the voting period has ended. | `finalise` | Wait until the ledger timestamp exceeds the proposal's `end_time`, then retry. |
| 10 | `AlreadyVoted` | The voter address has already cast a vote on this proposal. | `cast_vote`, `cast_vote_with_delegators` | Each address may vote exactly once. Use `has_voted(proposal_id, voter)` to check before calling `cast_vote`. |
| 11 | `NoVotingPower` | The voter holds zero governance tokens (and, since delegation, has none delegated to them either) at the time of voting. | `cast_vote`, `cast_vote_with_delegators` | Acquire a non-zero balance of the governance token, or accept a delegation, before casting a vote. |
| 12 | `ProposalNotPassed` | `execute` was called on a proposal that did not reach `Passed` status. | `execute` | Confirm the proposal status is `Passed` with `get_proposal(proposal_id)` before calling `execute`. |
| 13 | `AlreadyInitialized` | `initialize` was called on a contract that is already initialized. | `initialize` | Only call `initialize` once per deployed instance; deploy a new contract instance instead. |
| 14 | `VoteTallyOverflow` | Adding the vote's weight to the running tally would overflow `i128`. | `cast_vote`, `cast_vote_with_delegators` | This indicates an unrealistically large token supply/weight; verify token decimals and total supply configuration. |
| 15 | `InsufficientBalance` | The proposer's token balance is below `min_proposal_balance`. | `create_proposal` | Acquire enough governance tokens to meet the configured minimum before proposing. |
| 16 | `ProposalCooldown` | The proposer must wait for the cooldown period to expire before creating another proposal. | `create_proposal` | Wait until `proposal_cooldown` seconds have passed since your last proposal (see `get_config()`). |
| 17 | `TitleTooLong` | Proposal title exceeds the maximum byte length (256 bytes). | `create_proposal` (via `validate_string`) | Shorten the title to 256 bytes or fewer. |
| 18 | `DescriptionTooLong` | Proposal description exceeds the maximum byte length (4096 bytes). | `create_proposal` (via `validate_string`) | Shorten the description to 4096 bytes or fewer. |
| 19 | `InvalidTitle` | Proposal title is empty or otherwise fails validation. | `create_proposal` | Provide a non-empty title within the length limit. |
| 20 | `InvalidDescription` | Proposal description is empty or otherwise fails validation. | `create_proposal` | Provide a non-empty description within the length limit. |
| 21 | `InvalidDurationRange` | A duration parameter is outside the allowed range. | `create_proposal` (duration outside `[min_duration, max_duration]`), `update_timelock` (`new_duration` > 2,592,000 seconds / 30 days) | For `create_proposal`, keep `duration` within `[min_duration, max_duration]` (see `get_config()`). For `update_timelock`, keep `new_duration` at or below 30 days. |
| 22 | `QuorumExceedsSupply` | `quorum` exceeds the relevant token supply. | `create_proposal` (exceeds live total supply), `update_quorum` (exceeds the proposal's `supply_snapshot`) | Set a quorum at or below the total token supply (or the proposal's supply snapshot for `update_quorum`). |
| 23 | `VotingNotStarted` | The current ledger timestamp is before the proposal's `start_time`. | `cast_vote`, `cast_vote_with_delegators` | Wait until `env.ledger().timestamp() >= proposal.start_time`. |
| 24 | `InvalidNewAdmin` | New admin address supplied is invalid (e.g. zero address). *(Reserved — superseded in practice by `InvalidAddress` checks; kept for backward compatibility.)* | Not currently raised directly in `lib.rs`; validation now goes through `InvalidAddress`. | Ensure the new admin address is a valid, non-zero Stellar address. |
| 25 | `AdminVoteRestricted` | `restrict_admin_vote` is enabled and the caller is both the admin and the proposer. | `cast_vote`, `cast_vote_with_delegators` | Have a non-admin address cast the vote, or disable `restrict_admin_vote` at initialization. |
| 26 | `ContractPaused` | The contract is paused; state-changing operations are blocked. | Nearly all mutating functions: `create_proposal`, `cast_vote(_with_delegators)`, `finalise`, `execute`, `execute_parameter_change_override`, `cancel`, `update_quorum`, `update_max_proposals`, `update_timelock`, `transfer_admin`, `propose_admin_transfer`, `accept_admin_transfer`, `delegate`, `undelegate`, `upgrade` | Wait for the admin to call `unpause()`, or check `paused()` before submitting the transaction. |
| 27 | `NotPaused` | `unpause` was called on a contract that is not currently paused. | `unpause` | Only call `unpause` when `paused()` returns `true`. |
| 28 | `InvalidAddress` | An address parameter is the zero/default address. | `initialize`, `create_proposal` (proposer), `execute`/`execute_parameter_change_override`/`cancel`/`update_quorum`/`update_max_proposals`/`update_timelock`/`transfer_admin`/`propose_admin_transfer`/`pause`/`unpause` (admin, and `new_admin` for transfers), `cast_vote(_with_delegators)` (voter), `accept_admin_transfer` (new_admin), `delegate`/`undelegate` (delegator) | Supply a real, funded Stellar address rather than the zero address. |
| 29 | `ProposalCountOverflow` | The proposal ID counter overflowed (`u64::MAX` reached). | `create_proposal` | Not practically recoverable within one contract instance; this indicates the proposal counter is exhausted — deploy a fresh instance. |
| 30 | `TimelockNotExpired` | `execute` was called before the proposal's `execute_after` timestamp has been reached. | `execute` | Wait until `env.ledger().timestamp() >= proposal.execute_after`, then retry. Use `get_proposal(proposal_id).execute_after` to check the earliest eligible execution time. |
| 31 | `PendingAdminNotSet` | No admin transfer nomination is currently outstanding. | `accept_admin_transfer` | Have the current admin call `propose_admin_transfer` first. |
| 32 | `AdminTransferExpired` | The admin transfer acceptance window has passed. | `accept_admin_transfer` | Have the current admin call `propose_admin_transfer` again to restart the window. |
| 33 | `NotPendingAdmin` | The caller of `accept_admin_transfer` is not the address that was nominated. | `accept_admin_transfer` | Only the nominated `new_admin` address may accept the transfer. |
| 34 | `VotingPowerDelegated` | The caller has delegated their voting power and cannot vote directly. | `cast_vote`, `cast_vote_with_delegators` | Call `undelegate()` first if you want to vote with your own balance directly. |
| 35 | `CannotDelegateToSelf` | `delegate` was called with `delegator == delegate`. | `delegate` | Choose a different address to delegate to, or don't delegate at all. |
| 36 | `InvalidDelegateAddress` | The `delegate` address is the zero address. | `delegate` | Supply a real, funded Stellar address as the delegate. |
| 37 | `InvalidParameterChange` | A `ParameterChange` proposal's `ConfigKey`/value combination is invalid. | `create_parameter_change_proposal`, `execute_parameter_change_override` | Check the semantic constraints for the target `ConfigKey` (e.g. duration bounds, non-zero balances) before submitting. |
| 38 | `ParameterChangeNotSupported` | The proposal type does not support a parameter change operation. | Parameter-change execution path | Only call parameter-change execution on proposals created via `create_parameter_change_proposal`. |
| 39 | `TokenAlreadyRegistered` | The token is already registered for multi-asset voting. | Multi-token registration path | Check `get_config()` / the registered token list before re-registering. |
| 40 | `TokenNotRegistered` | The token is not registered for multi-asset voting. | Multi-token deregistration/weight-update path | Register the token first, or verify the address matches an already-registered token. |
| 41 | `CannotRemoveLastToken` | Removing this token would leave the DAO with zero voting tokens. | Multi-token deregistration path | Register a replacement voting token before removing the last one. |
| 42 | `InvalidWeightMultiplier` | The weight multiplier supplied for a voting token is zero. | Multi-token registration/weight-update path | Supply a weight multiplier greater than zero (100 = 1x). |
| 43 | `BatchTooLarge` | `get_votes` was called with more than `MAX_BATCH_VOTERS` (50) addresses. | `get_votes` | Split the voter list into batches of 50 or fewer addresses. |

### Known documentation/code gap

Two error names appear in `///` doc comments and `return Err(...)` call sites in
`contracts/governance/src/lib.rs` but are **not** defined in the
`ContractError` enum in `contracts/governance/src/types.rs`:

- `TooManyActiveProposals` — referenced at `lib.rs:181` (doc) and `lib.rs:318` (return site); guards the global active-proposal cap (see `storage.rs` "Active proposal cap and counter (#34)").
- `TransferWindowTooShort` — referenced at `lib.rs:897` (doc) and `lib.rs:918` (return site); guards `propose_admin_transfer`'s `window_secs` parameter.

This reference intentionally does **not** invent numeric codes for these two
names, since they are not present in the source-of-truth enum — doing so
would document a code that the compiled contract cannot actually return.
Whoever lands the fix for this (adding the missing variants to
`ContractError`, or renaming the call sites to reuse an existing variant)
should update this table in the same change. Flagging here rather than
silently omitting them so integrators aren't caught off guard if/when this is
resolved.

## Token Contract

Source: [`contracts/token/src/types.rs`](../contracts/token/src/types.rs)
(all `return Err(...)` sites below are in
[`contracts/token/src/lib.rs`](../contracts/token/src/lib.rs)).

| Code | Name | Description | Raised by | Resolution |
|------|------|-------------|-----------|------------|
| 1 | `AdminNotSet` | Token contract has not been initialized — no admin address is stored. | Internal admin lookup, used by `mint`, `burn`, `transfer_admin` | Initialize the token contract with an admin address before minting or configuring it. |
| 2 | `NotAdmin` | Caller is not the token contract admin. | `mint`, `burn`, `transfer_admin` | Sign the transaction with the admin keypair used during token initialization. |
| 3 | `InvalidAmount` | The amount provided to `transfer`, `mint`, or `burn` is zero or negative. | `transfer`, `mint` | Provide a positive integer amount. |
| 4 | `InsufficientBalance` | The sender's/owner's token balance is less than the requested transfer, `transfer_from`, or burn amount. | `transfer`, `transfer_from`, `burn` | Check the balance before initiating the operation and ensure sufficient funds. |
| 5 | `AllowanceExceeded` | The spender's approved allowance is less than the requested `transfer_from` amount. | `transfer_from` | Call `approve` to increase the allowance before calling `transfer_from`. |
| 6 | `InvalidNewAdmin` | New admin address supplied to `transfer_admin` is invalid. *(Reserved — in the current implementation `transfer_admin`'s zero-address check is reported as `InvalidAddress`; kept for backward compatibility.)* | Not currently raised directly; see `InvalidAddress`. | Ensure the new admin address is a valid, non-zero Stellar address. |
| 7 | `InvalidAddress` | An address parameter (`from`, `to`, `owner`, `spender`, `admin`, `new_admin`) is the zero/default address. | `initialize`, `transfer`, `approve`, `transfer_from`, `mint`, `burn`, `transfer_admin` | Supply a real, funded Stellar address rather than the zero address. |
| 8 | `AllowanceExpired` | The allowance's `expiry_ledger` is in the past relative to the current ledger sequence. | `transfer_from` | Call `approve` again with a fresh `expiry_ledger` before retrying `transfer_from`. |
| 9 | `InvalidExpiry` | `expiry_ledger` passed to `approve` is less than the current ledger sequence. | `approve` | Pass an `expiry_ledger` that is greater than or equal to `env.ledger().sequence()`. |

## Notes

- Error codes are scoped per contract — code `1` in the governance contract and code `1` in the token contract are independent.
- Errors are returned as `Result::Err(ContractError)` and surface as a `u32` in Soroban host diagnostics.
- Use `get_proposal(proposal_id)` and `has_voted(proposal_id, voter)` as pre-flight checks to avoid the most common errors.
- See [Known documentation/code gap](#known-documentationcode-gap) above for two error names used in the governance contract that are not yet formal enum variants.

## API Error Codes

All HTTP API responses from the VoteChain REST indexer use a consistent JSON error envelope:

```json
{
  "error": {
    "code": "NOT_FOUND",
    "message": "Proposal 42 not found",
    "details": []
  }
}
```

The `code` field is a machine-readable string constant. The `message` field provides a human-readable description. The `details` array is reserved for future use (e.g. field-level validation errors).

### HTTP Status Codes and Error Code Mapping

| HTTP Status | Error Code | Description | Example Trigger |
|-------------|------------|-------------|-----------------|
| 400 | `BAD_REQUEST` | The request body or query parameters are malformed or fail validation. | Invalid JSON body; `quorum` is zero; `duration` outside allowed range. |
| 401 | `UNAUTHORIZED` | The request lacks valid authentication credentials. | Missing or expired bearer token. |
| 403 | `FORBIDDEN` | The caller is authenticated but does not have permission for this action. | Non-admin address calling an admin-only endpoint. |
| 404 | `NOT_FOUND` | The requested resource does not exist. | Unknown proposal ID; unmatched route path. |
| 429 | `RATE_LIMITED` | The caller has exceeded the allowed request rate. | Proposer within cooldown period; too many requests per minute. |
| 500 | `INTERNAL_ERROR` | An unexpected server-side error occurred. | Unhandled exception; storage layer failure. |

### Contract Error to HTTP Status Mapping

When the indexer or API layer surfaces a smart contract error, the following mapping applies:

| Contract Error | HTTP Status | API Error Code |
|----------------|-------------|----------------|
| `ProposalNotFound` | 404 | `NOT_FOUND` |
| `NotFound` | 404 | `NOT_FOUND` |
| `InvalidQuorum` | 400 | `BAD_REQUEST` |
| `InvalidDuration` / `InvalidDurationRange` | 400 | `BAD_REQUEST` |
| `InvalidTitle` / `TitleTooLong` | 400 | `BAD_REQUEST` |
| `InvalidDescription` / `DescriptionTooLong` | 400 | `BAD_REQUEST` |
| `InvalidAmount` | 400 | `BAD_REQUEST` |
| `InvalidAddress` / `InvalidNewAdmin` / `InvalidDelegateAddress` | 400 | `BAD_REQUEST` |
| `QuorumExceedsSupply` | 400 | `BAD_REQUEST` |
| `BatchTooLarge` | 400 | `BAD_REQUEST` |
| `NotAdmin` | 403 | `FORBIDDEN` |
| `AdminVoteRestricted` | 403 | `FORBIDDEN` |
| `NotPendingAdmin` | 403 | `FORBIDDEN` |
| `AlreadyVoted` | 409 | `CONFLICT` |
| `ProposalNotActive` / `ProposalNotPassed` / `VotingStillOpen` / `VotingNotStarted` / `VotingPeriodEnded` / `TimelockNotExpired` | 409 | `CONFLICT` |
| `ProposalCooldown` | 429 | `RATE_LIMITED` |
| All other errors | 500 | `INTERNAL_ERROR` |

### Notes

- `500 INTERNAL_ERROR` responses never include stack traces or internal implementation details. Check server logs for diagnostics.
- The `details` array in the envelope is currently always empty. It will be used in a future version to carry per-field validation errors (e.g. `[{ "field": "quorum", "issue": "must be > 0" }]`).
- Route-not-found errors (`404 NOT_FOUND`) include the HTTP method and path in the message, e.g. `Route GET /api/unknown not found`.

## CI Validation

This table is maintained by hand rather than auto-generated. To keep it from
drifting, `scripts/check-errors-doc.sh` (invoked by the `docs-check` CI job)
verifies that every `ContractError` variant name declared in
`contracts/governance/src/types.rs` and `contracts/token/src/types.rs` also
appears as a `` `VariantName` `` entry somewhere in this file, and fails the
build if a variant is added to either enum without a matching row being added
here.
